Getting started

This guide explains how to use every section of Payday and, most importantly, in which order to do things, because many sections depend on each other.

How to use this guide#

  • New to Payday? Read Key terms below, then follow The complete workflow from start to finish.
  • Looking for one task? Use the search box or the menu on the left. Each module section lists its tasks in the order you will normally do them.
  • Every module section ends with What's next (where it leads) and a Quick reference table.

Key terms#

Term What it means
Client The production company you run payroll for (e.g. Northwind Productions). Clients own projects, classes and billing settings.
Project One production or job for a client (e.g. Summer Campaign 2026). Payroll is always run per project.
Employee A person's master record: name, SSN, address, default filing status, bank accounts. An employee isn't paid until they are added to a project.
Engagement An employee's job on one project: job title, class, pay type, rates, dates. Timecards and paychecks belong to engagements. One employee can have engagements on several projects.
Class (class code) A set of pay rules — overtime, meal penalties, night premium, allowances, fringes, deductions — that applies to every engagement assigned to it. Global classes live in Settings; each client has its own My Classes list, which is what engagements use.
Payroll Type Non-Union or Union. Union engagements take their rates and rules from a union contract.
Pay Type How an engagement is paid: Hourly, Daily Rate, Weekly Rate, Flat Deal, Monthly Salary, Fixed Salary, or Fixed Salary + Overtime.
Union A union or guild with its roles, dues and contracts. A contract holds rate schedules, overtime rules, allowances, fringes, residuals and budget tiers.
Loan-out company A worker's own company that is paid instead of the worker. Loan-out payments have state tax withholding instead of regular payroll taxes.
Agent A talent agent who can be linked to a worker on a project, with a commission.
Timecard The week's record of an engagement's time (Sunday–Saturday), meal breaks, leave, pay items, travel and prep/wrap.
Payroll run The calculation of all paychecks for one project and one pay period. Status moves Draft → Calculated → Locked (→ Voided if cancelled).
Invoice The bill to the client for a locked payroll run: wages, employer taxes, union fringes and the Payday service fee.
AICP template A budget structure (sections and line items). A project imports one, and timecard days can be linked to its line numbers.

How lists and forms work#

Most pages in Payday work the same way:

  • Search box above the list filters as you type.
  • Status filter next to Search — usually Active (default), Inactive or All. Deactivated records are hidden until you choose Inactive or All.
  • Reset clears the search and returns the filter to its default.
  • Click a column header to sort; click again to reverse.
  • Show 5 / 10 / 25 / 50 / 100 entries and page buttons at the bottom of the list.
  • Row actions are icons at the end of each row: View (eye), Edit (pencil), Deactivate (red circle) or Activate, and sometimes Delete (bin).
  • Required fields are marked with *. If something is missing, a message appears under the field when you save.
  • A short message (toast) appears at the top-right after saving, e.g. "Client Created Successfully".
  • Date fields open a calendar: click the month/year heading to jump to another year, then pick the day.
  • Entering a ZIP code fills State, County and City automatically.
  • Deactivating usually asks for confirmation. A deactivated record can be activated again from the Inactive (or All) list, unless the guide says the action can't be undone.

The complete workflow

This section walks through Payday from an empty system to a paid, invoiced payroll run. Follow the stages in order the first time. After that you will mostly repeat Stage 6 – Stage 8 every pay period.

Each step says where to do it and links to the module section with the full instructions.

The flow at a glance#

STAGE 1  One-time setup      Users · Settings · Tax Management
            │
STAGE 2  Client setup        Client → Billing Config → Classes (rules, allowances, fringes)
            │
STAGE 3  People              Employees · Loan-Out Companies · Agents
            │
STAGE 4  Unions (if needed)  Union → Roles, Dues → Contract → Rate Schedules, Rule Sets, Fringes…
            │
STAGE 5  Project setup       Project → import Union, Agents, Taxes, AICP template → Project Access
            │
STAGE 6  Engagements         Add each employee to the project (pay type, class, rates)
            │
STAGE 7  Timecards           Enter each week's time for every engagement
            │
STAGE 8  Payroll             Create run → Calculate → Review paychecks → Lock → Generate invoice

Stage 1 – One-time setup#

These items are shared by all clients and projects. Most of them are set up once and only changed occasionally.

  1. Invite the people who will use Payday. Users → Add User, choose a role. They receive an email to set their password. See Users and Login and profile.
  2. Check the reference lists in Settings. See Settings. - Locations – states, counties, cities, ZIP codes and countries used by every address field. - Project Types – the list offered when adding a project (e.g. Commercials, Television). - Departments – departments and their job titles. - Classes – optional global class library you can import into clients. - AICP Setup – budget templates. A template must be Published (Active) before a project can import it.
  3. Check taxes. Tax Management → Taxes: make sure there are Active federal and state taxes, each with a current version, for the states where you work. Tax Management → State Tax Withholding: make sure there is a rule for each state where loan-out workers will work. See Tax Management.

Tip: Taxes apply automatically. You don't attach them to employees — Payday picks the taxes that match the engagement's work location and the payroll run's pay date.

Stage 2 – Client setup#

  1. Add the client. Clients → Add Client (e.g. Northwind Productions). See Clients.
  2. Set up billing. Open the client → Billing Config → choose the Fee Model, Funding Model and Payment Terms → Save Configuration. This is needed later to generate invoices.
  3. Create the client's classes. Open the client → Classes → Add Classes → Create Manually (or Import Global Class from Settings). Typically: - a non-union class (e.g. NU-CREW) — open it and add the pay rules on its tabs:
    • Rules – Regular, Overtime (e.g. 8–12 hours × 1.5, 12+ × 2), 6th Day, 7th Day, Holiday, Meal Penalty, Night Premium (e.g. 22:00–06:00 × 1.1)
    • Allowances – e.g. Per Diem $50 per day worked, Mileage $0.67 per mile
    • Fringe Schedules – e.g. insurance, 401K
    • Additional Rules – leave pay, bonuses, deductions/reimbursements (e.g. Parking Deduction $10)
    • a union class (e.g. UN-CREW) — no rules needed; union engagements get their rates and overtime from the union contract.

Stage 3 – People#

  1. Employees. Employees → Add Employee for each worker (name, date of birth, gender, Federal Filing Status, SSN, email, address; workers under 18 also need work permit, guardian and Coogan account details). See Employees.
  2. Loan-out companies (only if you have loan-out workers). Loan-Out Companies → Add Company, then add a bank account and Set as Primary. See Loan-Out Companies.
  3. Agents (only for represented talent). Agents → Add Agent with a bank account. See Agents.

Tip: When you later add employees to a project, the search list first shows only the 5 newest employees. Note the exact names here so you can type them in the project.

Stage 4 – Unions (only if you have union workers)#

Build the union in this order (see Union):

  1. Union → Add Union (name, abbreviation, code, craft category, organization type, jurisdiction).
  2. Roles tab – the job classifications (e.g. Camera Operator, Key Grip).
  3. Dues tab – member dues (e.g. Working Dues 2.5% of earnings).
  4. Contracts tab → Add Contract (e.g. Commercial Agreement 2026). Open it and add: - Budget Tiers (optional, add before rate schedules) - Rate Schedules – one per role, with hourly/daily/weekly and prep/wrap/travel rates - Rule Sets – Overtime ladder (e.g. 0–8 h × 1, 8–12 h × 1.5, 12+ × 2) and Night Premium - Allowances, Fringe Schedules, Residual Rates

Stage 5 – Project setup#

  1. Add the project. Projects → Add Project (name, client, project type, production number, start/end dates, state). See Projects.
  2. Open the project and set up its tabs: - Unions → Import Union → select the union and tick its contract(s). Required before adding union employees. - Agents → Import Agent → choose the agent and commission. Required before linking an agent to an employee. - Taxes (optional) → import a tax to use project-specific rates, or State Tax Withholding → Adj. State Tax to use a project-specific loan-out withholding rate. - Budget → Import AICP Template (optional) → adjust sections, line items and estimates for this project. - Project Access → Add Access → grant access to roles (e.g. Bookkeeper) or specific users.

Stage 6 – Engagements (add employees to the project)#

Project → Employees → Add Employee. The wizard has these steps: Employee Info → Job Details → Pay Config → (Union Confirmation) → (Banking) → Dates → Verification. See Add an employee to a project in Projects.

Worker Employee Info Pay Config
Regular (W-2) non-union worker Classification Employee (W-2) Payroll Type Non-Union, choose the Pay Type and rates
Loan-out worker Classification Loan-Out Company + the company Non-Union (or Union); no Banking step
Union worker Classification Employee (W-2) Payroll Type Union → Union, Contract, Rate Schedule (rates fill in), then review and confirm the Union Confirmation step
Represented talent Tick Enable Agent Selection and choose the Agent as above

Every engagement also needs a Job Title, a Class Code (from the client's classes), a Work Location ZIP (decides which taxes apply), a State Filing Status, and a Hire Date.

Stage 7 – Timecards (every week)#

Open each engagement from the project's Employees tab. See Enter timecards in Projects.

  1. Go to the right week with Previous Week / Next Week (weeks run Sunday–Saturday).
  2. For each day worked, pick Time In, Time Out and any Meal Break times from the time lists, then click the row's Save (✓). - Flat Deal, Monthly Salary and Fixed Salary engagements don't record times — click IN to mark each day present. - Use LEAVE for leave days, Mark Day Specialty for 6th day / 7th day / holiday, AICP Line No. to assign a budget line.
  3. Add Pay Items, Travel Details and Prep/Wrap Time if needed.
  4. Check the Time & Pay Summary (an estimate; final amounts come from payroll).
  5. Missed something from an earlier week? Use the Adjustments tab.

Stage 8 – Payroll and invoicing#

See Payroll.

  1. Create the run. Payroll → Create Payroll Run (or Project → Payroll tab): choose the project, the pay period (the same Sunday–Saturday week as the timecards), the pay date and the pay frequency. Status: Draft.
  2. Calculate. Open the run → Calculate. One paycheck is created per engagement with pay in the period. Status: Calculated.
  3. Review. Click View Details on each paycheck: earnings, employee taxes (or loan-out withholding), employer taxes, deductions (e.g. union dues), reimbursements and net pay. If something is wrong, fix the timecard or engagement and click Re-Calculate.
  4. Lock. Click Lock Run and confirm. This can't be undone; it finalizes the paychecks and updates year-to-date totals. Status: Locked.
  5. Invoice. Click Generate Invoice. A Draft invoice appears under Projects → View Invoices (or Client → Projects → View Invoices). Preview it, then Issue it to send it to the client.
  6. Cancel a locked run only if necessary: Void Run with a reason. You can then create a new run for the same period.

When things change#

Change What to do
A global tax rate changes Add a new version in Tax Management with the new rate and start date (an active version's rate can't be edited). Projects that imported the tax show a green dot — Re-Import to take the change.
A state-specific rate changes (state override) Tax Management → open the tax → the version → Edit state override (or add or delete one). Projects that imported the tax show a green dot — Re-Import to take the change.
A loan-out withholding rate changes Edit the rule in Tax Management → State Tax Withholding. Projects with their own copy show a green dot — Re-Import.
A union agreement is renewed Renegotiate the contract, rate schedule or rule set in the Union module (the old one ends the day before the new one starts).
An agent's commission changes Project → Agents → Edit with a new effective start date.
A worker leaves a project Project → Employees → Deactivate (terminate) the engagement with a termination date.
A pay rule changes for one worker only Engagement → Rules & Allowances tab.

Login and profile

This section explains how to get into Payday and look after your own account. It covers setting your password from the invitation email, logging in, the account menu, editing your profile, changing your password, resetting a forgotten password, and logging out.

Setting your password, logging in and resetting a forgotten password happen while you are not logged in. Editing your profile and changing your password happen while you are logged in, from your Profile page.

Before you start#

  • An administrator must create your user account first (see Users → Add a user in Users).

Where to find it#

  • The login page is the first page you see when you open Payday and are not logged in.
  • Once you are logged in, your name appears at the bottom of the left side menu. Click it to open the account menu. See Use the account menu.

Password rules#

Every password you set in Payday (new account, change password, or reset) must meet these rules. The screen checks each rule as you type:

  • At least 8 characters
  • At least 1 uppercase letter
  • At least 1 number
  • At least 1 special character (for example !, @ or #)

The password and the confirmation must match.

Set your password from the invitation email#

When an administrator adds you as a user, you receive an invitation email. Your account stays Pending until you set a password.

  1. Open the email titled "Welcome to Payday – Set Your Password". It greets you by name and explains that your account is ready.
  2. Click Set Your Password in the email. If the button doesn't open, copy the link shown in the email into your browser.
  3. On the Set Your Password page, fill in the fields.
Field Required What to enter
Password Yes A new password that meets the password rules.
Confirm Password Yes The same password again.
  1. Click Activate Account.

Your account status changes from Pending to Active, and you are taken into Payday.

Important: The link in the invitation email is valid for 72 hours. If it has expired, ask your administrator to send a new invitation (see Users → Resend an invitation in Users).

Log in#

  1. Open the Payday login page.
  2. Enter your Email and Password.
  3. Click Sign In.

You are taken to your Dashboard. The side menu shows the modules available to your role.

Tip: If you can't remember your password, click Forgot password? on the login page. See Reset a forgotten password.

Use the account menu#

Click your name at the bottom of the left side menu. The account menu has three items:

Menu item What it does
Profile Opens your Profile page, where you can edit your details and change your password.
Settings Opens the Settings page (the same page as Settings in the side menu). See Settings.
Logout Logs you out of Payday. See Log out.

What the Profile page shows#

Card Contents
Personal Information First Name, Last Name, Email Address (editable with Edit Profile).
Account Information User Code, Account Type, Role, Member Since, Last Updated. These are read-only.
Security The Change Password option.

Edit your profile#

  1. Click your name at the bottom of the side menu, then click Profile.
  2. Click Edit Profile (top-right of the Personal Information card). The fields become editable.
Field Required What to enter
First Name Yes Your first name, e.g. Jane.
Last Name Yes Your last name, e.g. Smith.
Email Address Yes The email you use to log in, e.g. jane.smith@example.com.
  1. Change the fields you need.
  2. Click Save Changes. The button becomes available once you have changed a value.

You'll see the message "Profile updated successfully". The fields return to read-only, and your name updates in the account menu straight away.

To discard your changes, click Cancel before saving.

Note: If you change your Email Address, use the new address the next time you log in.

Change your password#

Use this when you know your current password and want to set a new one.

  1. Open your Profile page.
  2. In the Security section, click Change Password.
  3. In the Change Password dialog, fill in the fields.
Field Required What to enter
Current Password Yes The password you use today.
New Password Yes A new password that meets the password rules.
Confirm New Password Yes The new password again.
  1. Click Update Password.

You'll see the message "Password changed successfully" and the dialog closes. The new password works immediately; use it the next time you log in.

To close the dialog without changing anything, click Cancel.

Reset a forgotten password#

Use this when you can't remember your password. You do this from the login page, without logging in.

  1. On the login page, click Forgot password?.
  2. On the Forgot Password page, enter the Email address on your account.
  3. Click Send Reset Link.
  4. The page shows "Check your email — If an account exists for that email address, you will receive a password reset link shortly."
  5. Open the email titled "Payday – Reset Your Password" and click Reset Password. If the button doesn't open, copy the link shown in the email into your browser.
  6. On the Reset Password page, fill in the fields.
Field Required What to enter
New Password Yes A new password that meets the password rules.
Confirm Password Yes The new password again.
  1. Click Reset Password.

You return to the login page with the message "Password reset successfully. Please sign in." Log in with your email and the new password.

Important: The reset link is valid for 1 hour. If it has expired, repeat these steps to request a new link.

Note: For security, the confirmation message on the Forgot Password page is the same whether or not the email belongs to an account. If no email arrives, check that you typed the address correctly.

Log out#

  1. Click your name at the bottom of the side menu.
  2. Click Logout.

You return to the login page.

If your session expires#

Payday ends your session after a period of time. When your session expires, you are asked to log in again. Enter your Email and Password and click Sign In to continue working.

What's next#

  • Administrators: add the other people who will use Payday. See Users.
  • Set up the shared lists that the rest of Payday uses (locations, classes, project types, departments, AICP templates). See Settings.
  • Then create your first client. See Clients.

Users

The Users section is where administrators manage who can log in to Payday and what role each person has. Here you add users, send or resend invitations, edit user details, and deactivate or reactivate accounts.

Before you start#

  • You must be logged in with a role that can manage users, such as Payday Admin or Paymaster Admin.

Where to find it#

  1. In the left side menu, click Users.
  2. The User Management page opens ("Manage your users and their roles").

The list shows these columns:

Column What it shows
User Code The user's code, created automatically.
Name First and last name.
Email The email address the user logs in with.
Role The user's role. See Roles.
Status Pending, Active, Inactive or Locked.
Created The date the user was added.
Updated The date the user was last changed.
Actions The actions available for the user. These depend on the status.

By default the list shows Active users only, with the most recently created or updated users near the top. The heading shows the count, e.g. Users (12).

Roles#

Every user has one role.

Role Typical use
Payday Admin Full administration of Payday, including users and settings.
Paymaster Admin Administration of payroll work, including managing users.
Paymaster Only has access to the Projects section, and only to the projects they have been given access to.
Bookkeeper Only has access to the Projects section, and only to the projects they have been given access to.

Important: Users with a non-admin role (Paymaster or Bookkeeper) only see the projects they have been given access to. You grant this access on each project's Project Access tab. See Projects.

User statuses#

Status Meaning Actions available
Pending The user was added but hasn't set a password yet. Edit, Resend Invite
Active The user has set a password and can log in. Edit, Deactivate
Inactive The user was deactivated and can't log in. Edit, Activate

Time rules#

When Calculation Type is Time, choose an Earning Type:

Field Required What to enter

Some earning types add or change fields:

Earning Type Extra fields
Overtime OT Rule Type (required): Hourly (overtime counted on each day's hours, shown as OT Type: Daily in the rule details) or Weekly (overtime counted on the total hours in the week, e.g. Min 40 / Max 60 at 1.5x).

Regular, Holiday, 6th Day, 7th Day, Other No extra fields; just the ranges.

Clients

Each client has its own list of classes (the pay rules, allowances, fringes and deductions used for its workers), its own billing configuration (how the client is invoiced for payroll), and its own projects. Set up the client first. Projects, engagements, payroll runs and invoices all depend on it.

Before you start#

  • You need a user account with permission to manage clients, for example Payday Admin or Paymaster Admin.
  • To import a global class into a client, the class must already exist under Settings > Classes. See Settings.

Where to find it#

  1. In the side menu, click Clients.
  2. The Client Management page opens. The table shows Client Code, Name, Email, Phone, Location, EIN (masked), Contact, Client Type, Note, Status, Created, Updated and Actions.

By default, the list shows Active clients only. New clients are created as Active right away. There is no invitation or pending step.

  3. Click Add Client.

Manage client classes (My Classes)#

Client classes are separate from the global classes under Settings > Classes. You can create a client class from scratch, or import a global class as a starting point. Importing copies the class into the client. Changes you make to the client's copy don't affect the global class.

Important: When you add an employee to one of this client's projects, the Class Code dropdown in the Add Employee wizard lists only this client's My Classes. A global class appears there only after you add it to the client. See Projects → Add an employee to a project in Projects.

The My Classes table shows Label No. (created automatically), Class Code, Name, Description, Assigned Date, Updated Date, Status and Actions (View, Edit, Duplicate, Deactivate or Activate).

Non-union and union classes#

A non-union class needs its own rules. These rules tell Payday how to pay the worker: regular time, overtime, premiums, allowances, fringes and deductions.

A union class needs no rules. When an engagement uses a union payroll type, union pay rates, overtime, fringes and dues come from the union contract chosen on the engagement. You only need a class code to select in the Add Employee wizard, for example UN-CREW – Union Crew. See Union.

State tax withholding on loan-out payments#

Payday doesn't apply regular employee or employer payroll taxes to a loan-out paycheck. Instead, it applies the matching rule from Tax Management → State Tax Withholding for loan-out payments. See Tax Management.

How it works:

  • Withholding rules are set per state, and can be narrowed to a county and city. Each rule has a flat rate or progressive brackets, an effective period, and the options Withholding required and Resident exempt.
  • When the payroll run is calculated, the engagement's Work Location is matched to an Active rule. If a rule applies, the paycheck's Employee Taxes section shows one withholding line, for example Loan-out withholding - AZ (city), with the gross pay as the taxable amount and the rule's rate.
  • Resident exempt: when this is ticked on a rule, a worker whose home state is the same as the work state is not withheld.
  • States with no income tax are set up with Withholding required turned off, so nothing is withheld.

Example: Maria Garcia is paid through Garcia Creative LLC on Summer Campaign 2026 and works in Tempe, Arizona. Her paycheck shows one tax line, Loan-out withholding - AZ (city), at the Tempe rule's 3.00%.

Use a different withholding rate on one project#

A project can use its own copy of a withholding rule, for example to apply a different rate on one production.

  1. Open the project, click the Taxes tab, and open the State Tax Withholding sub-tab.
  2. Click Adj. State Tax, choose the rule, and click Adjust. You'll see the message "State Tax Adjusted Successfully".
  3. Edit the project's copy as needed. Changes affect only this project.
  4. If the rule is later changed in Tax Management, a green dot appears next to it on the project. Point at the dot to see the changes, then click Re-Import to take the new values. Re-importing replaces the project's own edits.

For full steps, see the State Tax Withholding sections in Tax Management and Projects.

Union

Use the Union section to set up unions, guilds and associations. For each union you record its Roles, Dues and one or more Contracts. Inside each contract you build the pay rules that a union engagement uses: base rates, overtime and night premium rules, allowances, employer fringes, residuals and budget tiers. Once a union is set up, you import it into a project and choose it when you add a union employee to that project.

Before you start#

  • You need an account with administrator or payroll-administrator permissions.
  • Unions are set up once and shared across the system. A project can only use a union after you import it into that project (see Using the union on a project).

How a union is organized#

A union is built in layers. Each layer depends on the one above it.

Level What it holds Where you add it
Union The organization that holds the agreement, and whether it Requires Local Scoping Union list → Add Union
Roles Job classifications the union covers (e.g. Camera Operator, Key Grip). Shared by every contract under the union. Union detail page → Roles
Dues Member dues (e.g. Working Dues). Shared by every contract under the union. Union detail page → Dues
Contract One negotiated agreement with an agreement type and effective dates Union detail page → Contracts
Locals Individual locals under a contract. Used only when the union Requires Local Scoping. Contract detail page
Rate Schedules Base rates for a role (hourly, daily, weekly) Contract (or Local) → Rate Schedules
Rule Sets Overtime and Night Premium rules Contract (or Local) → Rule Sets
Allowances Meal penalties, turnaround, per diem, mileage, kit rental, cell phone, fuel Contract (or Local) → Allowances
Fringe Schedules Employer and employee fund contributions (pension, health, vacation and more) Contract (or Local) → Fringe Schedules
Residual Rates Reuse payments by market Contract (or Local) → Residual Rates
Budget Tiers Production-budget bands that a rate schedule can be tied to Contract (or Local) → Budget Tiers

If the union Requires Local Scoping, the six rate tabs (Rate Schedules through Budget Tiers) live inside each Local. If it does not, they appear directly on the contract.

Recommended build order#

  1. Add the union. Decide whether it Requires Local Scoping.
  2. Add its Roles. A rate schedule can only use a role that already exists.
  3. Add its Dues.
  4. Add a Contract.
  5. Only if the union requires local scoping: add a Local under the contract.
  6. On the contract (or the local), add any extra Budget Tiers first, because each rate schedule picks its budget tier from that list.
  7. Add Rate Schedules, then Rule Sets, Allowances, Fringe Schedules and Residual Rates.
  8. Optionally, open a rate schedule and add rules that apply to that rate schedule only.
  9. Import the union into a project and add union engagements.

How lists work in this section#

Every list in this section (unions, contracts, roles, dues, locals and the six rate tabs) uses the same controls.

  • Search (top left of the list) filters as you type. On the Union list it matches the union name, union code and jurisdiction. On Roles it matches the role name. On Rate Schedules it matches the role name and scale code.

Tax Management

Tax Management is where you set up the global taxes that Payday uses when it calculates payroll, and the State Tax Withholding rules that apply to payments made to loan-out companies. Taxes defined here are shared across the whole application. You don't need to import them anywhere for them to work: a tax is applied automatically to every paycheck whose engagement Work Location matches the tax's jurisdiction and whose payroll run's Pay Date falls inside an active version of the tax.

A tax is built in layers:

Layer What it holds
Tax The name, type, who pays it (employee, employer or both) and the jurisdiction (federal, state, county or city)
Version An effective-dated rate setup with one calculation method (flat amount, flat percentage, progressive brackets or wage brackets)
Global rate or brackets The rate or brackets that apply everywhere the tax applies
State overrides (optional) An additional, state-specific tax charged on top of the version's global setup

Before you start#

  • You need an account with administrator or payroll-administrator permissions.
  • For State Tax Withholding rules, know the state (and, if needed, county and city) where loan-out workers will work.

Where to find it#

  1. In the side menu, click Tax Management.
  2. The Tax Management page opens. A toggle at the top right switches between two tabs: - Taxes (the default) — global payroll taxes. See Taxes below. - State Tax Withholding — withholding rules for loan-out payments. See State Tax Withholding.
  3. The Add Tax button at the top right adds a record to whichever tab is selected.

On the Taxes tab, the Taxes (N) list shows Tax Code, Tax Name, Description, Type, Jurisdiction, State, County, City, Payer, Current Rate, Status, Created, Updated At, Updated By and Actions (View, Edit, Deactivate or Activate, Delete).

Which version payroll uses#

Payroll uses the version whose effective period includes the payroll run's Pay Date. For example, a version starting January 1, 2027 applies to a run paid on January 8, 2027, even if the pay period started in December 2026.

Automatic end date for the previous version#

If you add a version that starts after an existing version with no end date, Payday closes the older version for you. Its end date is set to the day before the new version starts.

Example: a version effective from January 1, 2026 has no end date. You add a new version effective from November 1, 2026. The older version's Effective To becomes October 31, 2026.

Dates can't overlap an existing version#

If an existing version already has an end date, the new version must start after that end date. A start date that falls within the existing version's Effective From – Effective To period isn't accepted. You'll see the message "New version's effective date range conflicts with an existing ACTIVE version", and the dialog stays open so you can change the date.

Example: version 1.0 runs from October 1, 2026 to October 17, 2026. A new version starting October 10, 2026 is rejected. Choose October 18, 2026 or later as the Effective Start Date.

How withholding is applied in payroll#

Projects

A project is the production you run payroll for. It is the hub of the Payday workflow: you add employees to a project as engagements, bring in the unions, agents and taxes the project uses, set up its AICP budget, enter weekly timecards, and then run payroll and invoice the client from the project.

  • Billing, if you will invoice the client. The client needs a billing configuration before invoices can be produced. See Clients → Set up billing (Billing Config) in Clients.

Re-import after a global update#

When a tax is changed in Tax Management after you imported it, the imported copies are flagged so you can bring them up to date. Any of these changes flags the copies:

  • A new version is added.
  • A state override is edited (rate, wage base or dates) in any version, not only the current one.
  • A state override is added to or deleted from a version.
  • A state bracket or a global bracket is edited.

To bring the copy up to date:

  1. A small green dot appears at the top-right of the Tax Code in the Taxes list.
  2. Point at the green dot. The Tax Update Available dialog opens with the tax code and name, the message "This tax has been updated in Global Tax Management.", and a Changes summary. For example: - "A newer global version (2.0, effective 2027-01-01) is available. Rate changed from 1.450000% to 1.500000%." - "Pre-imported version 1.0 (effective 2026-10-01) was edited on the global side: - CA override rate changed from 0.300000% to 0.400000%." - "- Number of state overrides changed from 1 to 2. - TX override was added."
  3. Click Re-Import, or Close to leave it for now.

You'll see the message "Tax Reimported Successfully" and the green dot disappears. What changes depends on the update:

  • New version: the new version is added and tagged Current, with the rate from Tax Management. The previous version ends the day before the new one starts and its status becomes Superseded.
  • State override or bracket change: no new version is added. The existing version is updated with the values from Tax Management. For example, the CA override rate becomes 0.40%, a newly added override appears, and a deleted override is removed.

Re-importing replaces only the items that changed in Tax Management. Changes you made in the project to other items are kept. For example, if you set your own rate on a version and only a state override changed globally, your rate stays and the override takes the new global value. If you had also edited that same override, it takes the global value.

If the tax is deactivated in Tax Management, the dot appears with the change "The source global tax rate has been deactivated." The tax stays active in your project. The dot disappears when the tax is activated again in Tax Management.

Note: Editing only a version's Notes in Tax Management doesn't flag the imported copies.

Payroll

The Payroll section is where you pay the people working on a project. You create a payroll run for a project and pay period, calculate it to produce a paycheck for each engagement, review the paychecks, lock the run to finalise it, and generate an invoice to bill the client. If a locked run needs to be reversed, you can void it.

Before you start#

Make sure the following are in place before you create a payroll run:

  • [ ] A client with at least one class and an active billing configuration (needed to generate invoices). See Clients.
  • [ ] A project for that client. See Projects.
  • [ ] Engagements for each person to be paid, added on the project's Employees tab, with the correct pay type, rate and work location. See Projects → Add an employee to a project in Projects.
  • [ ] For union workers, the union imported into the project and selected on the engagement. See Union and Projects.
  • [ ] Timecards entered for the week you want to pay. See Projects.
  • [ ] The taxes for each work location set up in Tax Management and, for loan-out workers, a State Tax Withholding rule for the work location. See Tax Management.

Where to find it#

There are two ways to open payroll:

  • Side menu → Payroll opens the Payroll Runs page ("Manage payroll runs and process paychecks"). It lists every run across all projects.
  • Projects → open a project → Payroll tab lists only that project's runs. Its Create Payroll Run dialog has no Project field, because the project is already chosen. When you open a run from here, the back link reads Back to Payroll.

The Payroll Runs (N) list shows Run #, Run Name, Project, Client, Project Code, Pay Period, Pay Frequency, Pay Date, Status, Checks, Gross Pay, Net Pay and Actions (View). The project's Payroll tab shows the same columns without Project and Client.

  • Use Search to find a run.
  • The Status filter shows All runs by default. Choose Draft, Calculated, Locked or Voided to narrow the list.
  • Use Filters for more options, and Reset to clear them.
  • Click a row, or View, to open a run.

Understand payroll run statuses#

A payroll run moves through these statuses:

Status What it means What you can do next
Draft The run has been created but not calculated. It has no paychecks yet. Calculate
Calculated Paychecks have been produced. You can review them and recalculate after changes. Re-Calculate or Lock Run
Locked The run is final. Year-to-date totals are updated. Generate Invoice or Void Run
Voided The run has been reversed. Year-to-date updates are reversed. Nothing. You can create a new run for the same project and period.

Create a payroll run#

  1. Click Create Payroll Run (top right of the Payroll Runs page, or on the project's Payroll tab).
  2. In the Create Payroll Run dialog, fill in the fields below.
  3. Click Create Payroll Run.

You'll see the message "Payroll Run Created Successfully". The run appears in the list with Status Draft, no checks and $0.00 totals.

Field Required What to enter
Project Yes The project to pay (searchable). Each option shows "Project Name (Client Name)", e.g. "Summer Campaign 2026 (Northwind Productions)". Not shown when you start from the project's Payroll tab.
Pay Period Start Yes The first day of the period, e.g. Sunday Oct 4, 2026
Pay Period End Yes The last day of the period, e.g. Saturday Oct 10, 2026
Pay Date Yes The pay date, e.g. Oct 16, 2026. Tax versions are chosen by this date.
Pay Frequency Yes Weekly (default), Bi-Weekly, Semi-Monthly or Monthly
Run Name (Optional) No A friendly name, e.g. "Week 6 October". If left empty, the name becomes "{Project Name} — {start} to {end}".

Tip: Projects use a Sunday–Saturday week. Set the pay period to match the timecard week, for example Sunday 10/04/2026 – Saturday 10/10/2026.

About run numbers and periods:

  • The Run # is created for you in the pattern PR-{project code}-{pay period end date}-{code}, e.g. PR-{project code}-20261010-….
  • A project can have only one active run for a given pay period. If a run already exists for that project and period, you'll see "Failed to create run".
  • Once a run has been voided, you can create a new run for the same project and pay period.

Calculate a payroll run#

  1. Open a Draft run.
  2. Click Calculate.

You'll see the message "Payroll Run Calculated Successfully". The status becomes Calculated, Total Gross and Total Net are filled in, and the Paychecks table lists one paycheck for each active engagement with pay for the period.

The Paychecks table shows Engagement #, Employee Name, Job Title, Hours, Gross Earnings, Employee Taxes, Net Pay and Actions (View Details, eye icon).

Note: Hours shows 0 for Flat Deal, Monthly Salary and Fixed Salary engagements.

Re-calculate a payroll run#

If you correct a timecard or an engagement after calculating, recalculate the run to refresh the paychecks.

  1. Open a Calculated run.
  2. Click Re-Calculate.

You'll see the message "Payroll Run Calculated Successfully" and the paychecks and totals are updated.

Note: A locked run can't be recalculated.

View paycheck details#

  1. On a calculated or locked run, click View Details (eye icon) in a paycheck's row.
  2. The Paycheck Details dialog opens. Each section appears only when it has something to show.
  3. Click Close to return to the run.

Employee information#

Shows Employee Name, Engagement Number, Department, Job Title, Pay Rate, Pay Type, Payroll Type, Work State and Filing Status.

  • Pay Type shows the engagement's pay type, for example Hourly, Daily, Weekly, Flat, Monthly Salary, Salary Fixed or Salary Plus Ot.
  • Payroll Type shows Non Union or Union.
  • Work State shows the two-letter state of the engagement's work location, for example CA.
  • Filing Status shows the employee's filing status, for example Single.

Employee taxes#

One line for each employee tax, with its Taxable amount and Rate, followed by Total Employee Taxes. Which taxes appear depends on the engagement's work location, the run's Pay Date and the taxes set up in Tax Management. A tax paid by both employee and employer appears here as {Tax Name} (Employee), and its employer part appears under Employer taxes as {Tax Name} (Employer). Each line's rate comes from the tax version's Employee Rate (%) or Employer Rate (%); see Tax Management → Split rates in Tax Management.

Loan-out withholding#

On a loan-out paycheck, Employee Taxes shows one line from the matching State Tax Withholding rule, named Loan-out withholding - {state}. For example, Maria Garcia (paid through Garcia Creative LLC) working in Tempe, Arizona shows Loan-out withholding - AZ (city) at 3.00%. No other employee or employer taxes appear on a loan-out paycheck. See Tax Management → State Tax Withholding for loan-out payments in Tax Management.

Employer taxes#

Employer-side taxes with their Taxable amount and Rate, followed by Total Employer Taxes. Employer taxes are billed to the client on the invoice. The employer part of a tax paid by both sides appears here as {Tax Name} (Employer).

Deductions#

Each deduction and Total Deductions. For example, a union worker on Sample Crew Union shows the union's Working Dues (such as 2.5% of gross pay). Deductions from class rules and pay items also appear here.

Reimbursements#

Each reimbursement and Total Reimbursements, from reimbursement rules or pay items.

Net pay summary#

Gross Earnings − Total Employee Taxes − Total Deductions + Total Reimbursements = Net Pay. This matches the Net Pay column in the Paychecks table.

How each pay type is paid#

Pay Type How it is timecarded How it appears on the paycheck

Daily Rate Time In / Time Out each day Regular for the days worked, plus overtime beyond the standard hours per day
Weekly Rate Time In / Time Out each day Regular for the weekly rate, plus any overtime

Lock a payroll run#

Locking finalises the run so it can be invoiced and updates each employee's year-to-date totals.

  1. Open a Calculated run and review the paychecks.
  2. Click Lock Run.
  3. The Lock Payroll Run dialog asks you to confirm. Locking prevents further edits and updates year-to-date totals.
  4. Click Lock Run (or Cancel).

You'll see the message "Payroll Run Locked Successfully". The status becomes Locked, and the Re-Calculate and Lock Run buttons are replaced by Void Run and Generate Invoice.

Important: Locking a run can't be undone. Check every paycheck before you lock. To reverse a locked run, you must void it.

Generate an invoice#

The invoice covers the run's wages, employer taxes, union fringes and the Payday service fee.

  1. Make sure the client has an active billing configuration (Clients → open the client → Billing Config tab). See Clients.
  2. Open a Locked run.
  3. Click Generate Invoice.

You'll see the message "Invoice Generated Successfully". A Draft invoice is created for the project, for example INV000001, with:

  • Invoice Date — today
  • Billing Period — the run's pay period
  • Due Date — today plus the client's payment terms (for example Net 30)

Note: Each run produces one invoice. Clicking Generate Invoice again doesn't create a second invoice.

Find and preview the invoice#

  1. Go to Projects and click the View Invoices icon in the project's row (or Clients → open the client → Projects tab → View Invoices).
  2. The Invoices page lists the project's invoices. See Projects → Project invoices in Projects.
  3. Click Preview invoice (eye icon) to open the invoice.

The invoice preview shows:

  • the From and Bill To details (the client and project)
  • Invoice Type, invoice and due dates, Billing Period and Pay Date
  • a Per-Worker Breakout with Worker, Role, Wages, Employer Tax, Union Fringe and Total
  • a Summary with the wages subtotal, the employer payroll taxes subtotal, the PayDay Service Fee (from the billing configuration), Grand Total, Amount Paid and Balance Due

You can zoom, rotate, download and print the preview.

Issue the invoice#

  1. On the Invoices page, click Issue invoice (check icon) on a Draft invoice.
  2. The Issue Invoice dialog explains that issuing finalises the invoice, locks its line items, sets the due date and emails the invoice PDF to the client.
  3. Click Issue Invoice (or Cancel).

The invoice is emailed to the client in the background; you don't need to wait. To send it again later, click Resend invoice (send icon) on a sent invoice and confirm with Resend Invoice.

Important: Issuing and resending can't be undone, and both email the client.

Void a payroll run#

Void a locked run to reverse it.

  1. Open a Locked run.
  2. Click Void Run.
  3. The Void Payroll Run dialog explains that voiding reverses any year-to-date updates made when the run was locked.
  4. Enter the Reason for Voiding (required), for example "Incorrect timecard hours for Alex Johnson".
  5. Click Void Payroll Run (or Cancel).

The run's status becomes Voided and it stays in the list for your records. You can now create a new run for the same project and pay period.

Important: Voiding can't be undone.

What's next#

  • Correct any timecard or engagement problems found during review, then Re-Calculate before locking. See Projects.
  • After locking, generate the invoice and issue it to the client. Track its status on the project's Invoices page. See Projects → Project invoices in Projects.
  • Repeat the process for the next pay period: enter timecards, create a new run, calculate, lock and invoice.
  • To change tax rates or withholding rules for future runs, see Tax Management.
